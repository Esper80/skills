# PR 전달 계약

## 범위와 권한

사용자 요청과 저장소 제약을 우선합니다. 로컬 수정·논리 커밋·검증은 요청한 준비 작업에 포함될 수 있습니다. 원격 push·PR 작성·댓글·병합·배포는 해당 전달 단계가 요청되거나 승인됐는지 확인합니다. PR 생성 요청은 필요한 commit·push를 포함하지만 병합·배포까지 포함하지 않습니다. 병합이 자동 배포를 일으키면 운영 반영도 승인 범위여야 합니다.

사용자나 다른 작업의 변경을 보존합니다. 공유 이력 재작성·강제 push·파괴적 정리는 별도 권한 없이 수행하지 않습니다. SSH 읽기는 사용자 기본 허용 범위이며 원격 변경은 명시적 허가가 필요합니다.

## 검증

- 변경의 관찰 가능한 결과를 검증하고 저장소의 필수 local·CI 게이트를 완료합니다. 모든 비사소한 변경에 전체 CI를 추가로 강제하지 않습니다.
- 검사 생략·대체 검증은 현재 사용자 요청과 프로젝트 정책이 명시적으로 허용한 범위에만 적용합니다. 생략·실패·미실행을 통과로 표시하지 않고 나머지 보호 규칙은 유지합니다.
- 직접 경로와 회귀 위험부터 확인합니다. 공유 계약·보안·데이터·빌드·배포 영향이 있으면 필요한 통합 검사와 저장소 게이트로 넓힙니다. 문서·비실행 metadata에는 문구·링크·구조 검사가 적합합니다.
- 실제 동작을 보장할 의미가 있을 때 테스트를 추가합니다. 구현을 그대로 복제하는 테스트나 무관한 검사는 붙이지 않습니다.
- 검증 대상 commit 또는 코드 snapshot, 명령·시나리오, 결과, 미실행 항목을 기록합니다. commit 생성으로 SHA만 바뀌고 검증한 코드·환경이 같으면 그 대응을 기록해 증거를 재사용할 수 있습니다.
- 코드·설정·기준·환경이 바뀌면 영향을 평가해 무효화된 검사만 갱신합니다. 같은 결과를 로컬리뷰·CI 대응·최종 보고마다 반복하지 않습니다.
- 사용자가 로컬리뷰를 요청하면 현재 diff의 검토와 지적사항 처리를 완료합니다. 특정 receipt·도구는 저장소 정책이나 요청이 요구할 때만 사용합니다.
- 필수 검사 실패나 미실행을 성공·병합 가능으로 보고하지 않습니다. 게시가 승인됐고 필수 검증을 아직 마칠 수 없다면 제한과 남은 검증을 명시한 draft로 공유할 수 있습니다. 저장소의 더 엄격한 게시 규칙은 유지합니다.

## 결과

구현, 검증, 원격 게시, 리뷰, 병합·배포 상태를 구분합니다. 요청한 단계의 결과와 중요한 남은 제한을 보고하고, 다음 단계의 승인을 임의로 가정하지 않습니다.
