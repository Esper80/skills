# 작업 환경과 worktree

구현 환경을 선택·재개·정리할 때 적용합니다. 프로젝트가 지정한 격리 규칙을 우선합니다.

- 사용자가 지정한 checkout이나 안전한 현재·기존 worktree를 재사용합니다. 동시 작업·다른 변경과의 분리 또는 저장소 정책상 격리가 필요할 때 worktree를 만듭니다. 읽기 전용 조사에는 만들지 않습니다.
- 관련 `git status`, 브랜치·diff·기준 commit을 확인하고 사용자 변경을 보존합니다. 구현에 필요한 기준을 확인하되 모든 작업에 최신 원격 기본 브랜치를 강제하지 않습니다.
- 새 환경은 프로젝트 경로 규칙을 따르고 사용 중인 작업과 충돌하지 않게 만듭니다. Codex 관리 worktree 도구가 있으면 연결된 작업 환경을 확인하고 해당 도구를 우선합니다.
- 기본 checkout을 시작·종료마다 전환·동기화하지 않습니다. 필요한 경우에만 안전한 fetch·fast-forward를 수행하고 dirty·diverged·사용 중인 checkout을 강제 전환하지 않습니다.
- 무거운 검증이나 실행 환경 교체 전 관련 프로세스·컨테이너·포트·볼륨의 공유 여부를 확인합니다. 다른 작업의 자원을 중지·삭제하지 않습니다.
- 결과·미반영 commit·untracked·필요한 ignored 자료가 남으면 보존합니다. 실패·취소를 이유로 증거와 재개할 작업을 삭제하지 않습니다.
- 정리 전 정확한 경로, 결과의 보존·반영 근거, 사용 중인 프로세스·bind mount를 확인합니다. 관리 worktree는 `archive_worktree`, 일반 worktree는 안전한 `git worktree remove`를 사용합니다.
- 강제 제거·재귀 삭제·광범위 Docker prune은 별도 승인 없이 사용하지 않습니다. 브랜치 삭제는 worktree 제거와 별개로 판단합니다. 정리 후 상태를 확인하고, 남긴 환경은 경로와 이유를 보고합니다.
