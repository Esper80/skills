# Review Radius

리뷰 댓글을 결함의 단서로 보고 코드·계약·동작으로 타당성을 확인합니다. 사용자 요청과 프로젝트 제약을 우선하며 같은 원인을 고치되 명백한 범위 확대는 승인 없이 진행하지 않습니다.

## 기본 흐름

- 단일하고 명확한 PR 의견은 `pr-workflow`에서 직접 처리합니다. 이 스킬은 반복·연관 결함 조사에 사용합니다.
- 현재 PR head·diff·관련 스레드와 이미 처리한 내용을 확인합니다. 단순 상태 질의에는 수정 루프를 시작하지 않습니다.
- 타당한 지적·오탐·중복·이미 해결됨·추가 판단 필요를 구분합니다. 해당 경로와 같은 원인의 호출자·형제 경로·오류 처리를 필요한 만큼 조사합니다.
- 승인된 범위의 원인 수정과 영향에 맞는 검증을 완료합니다. 유효한 검증은 재사용하고 변경으로 영향을 받은 검사만 갱신합니다. 보안·데이터·배포·반복 회귀 위험은 필요하면 독립 검증을 받습니다.
- 사용 가능한 기존 로컬 리뷰 절차와 유효한 결과를 재사용합니다. 선택 도구의 부재만으로 일반 리뷰를 중단하지 않으며, 사용자·저장소가 명시한 필수 절차는 임의로 생략하거나 통과로 표시하지 않습니다.
- GitHub 답글·해결·push는 요청된 전달 범위에서 수행합니다. 관련 원격 head가 바뀌었는지 확인하고 완료한 내용만 해결 처리합니다. PR 쓰기·CI·병합 준비는 `pr-workflow`를 따르며, 요청한 단계의 필수 처리가 끝나면 확인을 종료합니다.
- 새 피드백이 같은 작업 안의 타당한 수정이면 이어 처리할 수 있습니다. 횟수만으로 중단하지 않습니다. 같은 실패가 반복되거나 전략·계약·범위 변경이 필요하면 원인을 재평가하고 필요한 사용자 결정을 구체적으로 제시합니다. 범위 밖 발견은 보고하되 해결 가능한 원래 작업을 불필요하게 중단하지 않습니다.
- 처리한 원인·관련 조사 범위·검증·남은 위험과 실제 전달 상태를 간단히 보고합니다. 리뷰 완료·QA 통과·원격 전달을 서로의 증거로 대체하지 않습니다.

## 필요할 때만 읽기

- 반복·수렴 문제를 위한 코드 탐색: [탐색과 증거](references/code-navigation.md).
- 명시적으로 요청되거나 저장소가 요구하는 지속 controller 캠페인: [엄격 리뷰 흐름](references/strict-review-workflow.md). 이 모드에서만 governor·campaign·guard·고정 cutoff·수정 횟수 제한을 적용합니다.
- 기존 엄격 캠페인을 재개하는 경우 해당 상태와 [실행 제어](references/executable-session-control.md)를 확인합니다. 기존 기록을 삭제하거나 중단 상태를 일반 모드로 우회하지 않습니다.
- 독립 QA·릴리스 검증이 요청되거나 위험상 필요한 경우 사용 가능한 `traceknot`을 적용할 수 있습니다. 단순 runtime/UI 변경만으로 이 도구를 필수화하지 않습니다.

일반 흐름에는 persisted controller, 매 patch 토큰, 두 번 수정 후 중단, 모든 증거의 SHA 변경 시 재실행, QA Board를 추가 완료 조건으로 요구하지 않습니다. 저장소의 실제 필수 검사와 운영 안전 경계는 그대로 지킵니다.
