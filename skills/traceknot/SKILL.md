# Traceknot

관찰 가능한 기준과 실제 증거로 검증합니다. 사용자 요청과 프로젝트의 필수 검사를 우선합니다. QA 결과는 구현·게시·전체 작업 완료와 구분합니다.

## 기본 QA

- 변경 대상·요구사항·중요 계약에서 합격 기준과 위험을 정합니다. 없는 기준은 요청에서 도출했다고 밝힙니다. 관련 문서만 읽고 모든 QA에 전면 문서 수집이나 정형 ID 목록을 요구하지 않습니다.
- 직접 변경 경로부터 확인하고 위험에 맞게 오류·경계·회귀·통합 검사를 선택합니다. 보안·데이터·동시성·배포 영향은 필요한 독립 증거와 복구 검증을 포함합니다. 낮은 위험 작업을 별도 agent나 context 부재로 중단하지 않습니다.
- 버그는 가능한 경우 수정 전 재현하고 같은 조건으로 수정 후 확인합니다. UI는 영향을 받은 실제 화면·흐름과 필요한 viewport·상태를 확인합니다. 무관한 모든 UI 스트레스 profile이나 승인 artifact를 일괄 요구하지 않습니다.
- 검사한 코드·환경, 명령·시나리오, 실제 결과와 제한을 기록합니다. agent 완료 주장·녹색 CI·화면 캡처 하나를 모든 기능의 증거로 쓰지 않습니다. 확인하지 않은 위험은 미확인으로 남깁니다.
- 독립 검수는 위험이나 프로젝트 계약에 맞게 수행합니다. 같은 에이전트의 자체 검사를 독립 검증으로 부르지 않습니다. 별도 검수자가 소스·기록을 대조한 범위와 시험을 직접 재실행한 범위를 구분해 보고합니다.
- 복구 절차·복구점 확인과 실제 복구 실행을 구분해 기록합니다. 필요한 로컬 교체·복구 시험은 수행하고, 운영 변경·실제 발송·운영 복구 실행은 현재 승인 범위에서 진행합니다. 이미 승인된 시험의 승인을 반복해서 묻지 않습니다.
- 유효한 기존 결과는 재사용합니다. 변경·실패·남은 의문이 없으면 같은 검사나 더 넓은 검사를 반복하지 않습니다. 도구 설치·Board 생성은 일반 검증의 선행 조건이 아닙니다.
- 결과를 `PASS`, `FAIL`, `BLOCKED`, `INCOMPLETE`로 구분합니다. `PASS`는 필요한 검사와 합격 기준이 충족된 경우만 사용합니다. 모든 필수 검사가 통과하고 잔여 위험이 명시적으로 수용된 경우에만 `PASS_WITH_ACCEPTED_RISK`로 구분합니다. 위험 수용으로 필수 검사 실패·미실행을 통과로 바꾸지 않습니다.

## 작업별 참조

일반 모드에서는 참조 문서의 기술·관찰 기준 중 현재 위험에 필요한 부분만 사용합니다. 그 문서의 전면 trigger scan·정형 ID·영수증·독립 producer·전체 profile 요구는 엄격 모드를 선택했거나 프로젝트가 실제로 요구하는 경우에만 적용합니다.

- 테스트 기법·추적 관계가 필요할 때: [테스트 기법](references/test-techniques.md), [추적 관계](references/traceability.md).
- 보안·데이터·동시성·반복 결함의 심층 조사: [위험 발견](references/adversarial-risk-discovery.md). 일반 QA의 일괄 trigger scan으로 적용하지 않습니다.
- 화면 구성·반응형 동작이 실제 범위에 포함될 때: [시각 구성](references/visual-composition.md). 전체 인증 profile은 정책상 필요한 경우에만 선택합니다.
- proof-carrying evidence·기계 검증·엄격 통합이 요청되거나 요구될 때: [엄격 QA 흐름](references/strict-qa-workflow.md). 해당 profile의 실제 증거·독립성·계약을 보존하며 불충족을 통과로 표현하지 않습니다.
- 정형 QA Board·지속 기록이 요청되거나 요구될 때: [QA Board](references/qa-board.md). 사용 가능한 capability를 확인하고 게시 실패를 QA 결과와 분리합니다. 자동 설치·업데이트·외부 전송은 시작하지 않습니다.
- 보고가 필요할 때: [완료 보고](references/completion-report.md). 일반 보고는 검증 결과와 중요한 제한 중심으로 작성합니다.

별도 도구의 부재만으로 가능한 로컬 QA를 멈추지 않습니다. 실제 필수 검증을 할 수 없다면 정확한 제한과 남은 작업을 보고합니다. 기계 검증용 실행 파일·schema·기존 엄격 기록은 임의로 바꾸지 않으며, 진행 중인 엄격 QA의 기록·미완료 의무를 일반 모드의 PASS로 대체하지 않습니다.
